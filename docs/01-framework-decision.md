## 结论

推荐采用：**Astro 官方精简项目 + TypeScript 严格模式 + Tailwind CSS + Astro Content Collections**。

网站视觉可以使用现代 SaaS 风格，但不直接套用完整 SaaS 营销模板。

## 为什么这样选择

“找机场”的主体是超过 100 篇的评测、测速、教程和对比内容。它需要的是稳定的内容模型、分类、筛选、SEO、内链和易维护性，而不是 SaaS 官网常见的定价、产品功能、客户案例和登录面板。

从精简项目开始的优势：

- 文件少，新手更容易理解。
- 不继承模板中大量无用页面和组件。
- 可以围绕 36 家机场建立统一的数据模型。
- 评测、测速和机场资料可以互相关联。
- 更容易控制 SEO、页面速度和结构化数据。
- 后续改版时不会被第三方模板结构限制。

## 不推荐作为基础的方案

### 完整 SaaS 模板

优点是首页初看漂亮；缺点是内容架构通常不适合大型评测博客，需要删除和重写很多内容。

### 直接使用 AstroWind

AstroWind 是成熟的开源营销与博客模板，适合快速展示型网站，但“找机场”仍需重做内容模型、品牌目录、测速数据和对比系统。对新手而言，先理解其大量组件再改造，未必比精简搭建更省时间。

### 引入 React、Vue 或数据库

第一版没有必要。Astro 自身足以完成静态内容、分类、标签、搜索数据和推广链接管理。只有出现明确的动态功能需求时再增加依赖。

## 拟锁定的技术基础

- Astro：使用创建项目时的当前稳定版本
- TypeScript：严格模式
- 样式：Tailwind CSS
- 内容：Markdown / MDX + Content Collections
- 输出方式：静态 HTML
- 包管理器：pnpm
- 版本管理：Git
- 远程仓库：GitHub（本地完成后连接）
- 托管：Cloudflare
- 首版不使用：数据库、用户系统、React、Vue、在线 CMS

## 第 1 步实施范围

确认方案后，本步骤只完成基础工程：

1. 初始化 Git 仓库。
2. 创建 Astro 项目。
3. 配置 TypeScript 和 Tailwind CSS。
4. 建立基础目录和站点配置。
5. 添加开发、构建和预览命令。
6. 创建最小首页，证明框架正常工作。
7. 完成本地构建测试。
8. 编写新手运行说明。

本步骤暂不制作正式首页样式，不批量创建文章，也不连接 GitHub 或 Cloudflare。
